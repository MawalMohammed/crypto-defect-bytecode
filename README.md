# Learning to Detect Cryptographic Defects in Ethereum Smart Contracts from Bytecode

Reproduction artifacts for the paper *"Learning to Detect Cryptographic Defects in
Ethereum Smart Contracts from Bytecode."* Source-level analyzers for cryptographic defects
(signature replay, signature malleability, insufficient signature verification,
Merkle-proof misuse, hash collisions, weak on-chain randomness) need verified
Solidity source, but fewer than 1% of deployed contracts are source-verified. This
project distills a source-level analyzer (the *teacher*) into **bytecode-only**
detectors (the *students*), so detection works on the unverified majority of on-chain
code. Everything here runs on a single consumer laptop at zero cloud cost.

## Headline results (test set, leakage-free clone-cluster split)

Per-class average precision (AUPRC) of the gradient-boosted opcode-n-gram detector:

| Class | AUPRC | | Class | AUPRC |
|---|---|---|---|---|
| SM  (signature malleability)        | 0.934 | | SF  (signature front-running) | 0.564 |
| CCR (cross-chain replay)            | 0.928 | | SSR (single-contract replay)  | 0.391 |
| CSR (cross-contract replay)         | 0.881 | | HC  (hash collision)          | 0.239 |
| WR  (weak randomness, chain attrs)  | 0.857 | | MR  (Merkle replay)           | 0.232 |
| ISV (insufficient sig. verification)| 0.818 | | MF  (Merkle front-running)    | 0.225 |
| WRT (weak randomness, tx attrs)     | 0.625 | | | |

Representation comparison (mean AUPRC): **XGBoost 0.611 > CNN 0.489 > Transformer
0.326**. In the wild, 56% of high-confidence flags land on *unverified* contracts.
The full per-class numbers, confidence intervals, ablations and interpretation are
regenerated by the pipeline described below.

## Repository layout

```
scripts/     the full pipeline (fetch -> disassemble -> cluster -> split -> train -> evaluate -> figures)
data/        dataset.csv -- the only provided input: per contract, its 12 defect labels,
             its clone-cluster id, and its train/validation/test split
```

Running the pipeline creates `data/` and `results/` artifacts locally (bytecode, opcodes,
clustering, metrics, figures, trained models); none of these are shipped.

## What is and is not included

This is a minimal, reproduce-from-scratch package: the pipeline scripts and the single
essential input, `data/dataset.csv`. Every other artifact is an *output* that the
pipeline regenerates, and is therefore not shipped:

- Bytecode and opcode dumps (`bytecode.jsonl`, ~1.3 GB; `opcodes.jsonl`, ~2.2 GB),
  produced by `fetch_bytecode.py` and `extract_opcodes.py`.
- Clone clustering, split files, metrics, reports, figures and trained models, produced
  by the remaining scripts.

`data/dataset.csv` carries the 12 defect labels per contract. These labels come from a
source-level cryptographic-defect analyzer; see the paper's reference [1] (Zhang et al.,
IEEE TSE 2025) for the analyzer and the underlying contract corpus.

## Requirements

Python 3.10+. Install with:

```
pip install -r requirements.txt
```

CPU is enough for the boosting baseline, ablations, interpretation and figures. The
neural arms (`train_cnn.py`, `train_transformer.py`) use a CUDA GPU (they were trained
on a 4 GB card with mixed precision).

## Reproducing the results

> **Paths:** each script sets its input/output locations in path constants near the
> top (originally absolute Windows paths). Edit those constants to point at your clone
> of this repo before running.

The labels, clone-cluster ids and train/validation/test split are provided in
`data/dataset.csv`, so the partition is exactly reproducible. Run the steps in order to
rebuild every result from scratch:

1. **Bytecode** — `python scripts/fetch_bytecode.py`. It reads an address list; the
   labelled addresses are column 1 of `data/dataset.csv`
   (`tail -n +2 data/dataset.csv | cut -d, -f1 > contract-list.txt`). Keyless public
   JSON-RPC, resume-safe.
2. **Disassembly** — `python scripts/extract_opcodes.py` (bytecode -> opcode sequences,
   strips the metadata trailer).
3. **Clone clustering** — `python scripts/dedup_clusters.py` (exact + MinHash/LSH near
   duplicates; reproduces `data/clusters.csv`).
4. **Splits** — `python scripts/make_splits.py` (cluster-level 70/10/20; reproduces
   `data/dataset.csv`).
5. **Baseline (RQ1/RQ2)** — `python scripts/train_baseline.py` -> `baseline_metrics.csv`.
6. **Neural arms (RQ2)** — `python scripts/train_cnn.py`, `python scripts/train_transformer.py`.
7. **Interpretation + imbalance (RQ4/RQ3)** — `python scripts/run_rq3_rq4.py`.
8. **Hardening** — `python scripts/run_harden.py` (gold-label eval, rule baselines,
   3-seed bootstrap CIs).
9. **In-the-wild study (RQ5)** — `python scripts/rq5_wild.py`, then
   `ETHERSCAN_API_KEY=<key> python scripts/annotate_wild.py` for the verification column.
10. **Figures** — `python scripts/make_figures.py` -> `results/figs/`.

Fixed seeds and deterministic hashing make the splits and headline numbers exactly
reproducible.
